# Remaining roadmap completion

This checklist closes the finite survivor-game implementation of the expansion notes in RESEARCH.md. Vanilla relationships inform names and progression; numerical rules and combat remain original adaptations. Existing saves keep their current builds.

- [x] Full Classic talent structure: 27 trees, original rank caps, rows and explicit prerequisites; 51 points from levels 10–60; reviewed switching from the existing compact path.
- [x] Class techniques: three further specialization techniques per class, including timed support abilities, with trainer reviews and four-spell preparation.
- [x] Equipment instances: independently owned duplicate drops and crafted copies, deterministic bounded rolls, per-copy condition, binding, enchanting and destruction.
- [x] Attributes and resistances: five primary attributes and five magical resistance schools, equipment presentation and actual combat effects.
- [x] Endgame: another outdoor region and dungeon route, guardian mechanics, concluding faction and profession objectives, and a visible completed journey.
- [x] Directional presentation: distinct front/back facing for heroes with existing movement, casting, death and reduced-motion controls.
- [x] Optional cooperative play: a second local player, independent movement and attacks, shared encounters, revival and once-only rewards. Online networking is outside this implementation.
- [x] Final validation: unit and browser coverage of the new transactions, combat and save imports; production build, formatting, repository asset audit; updated user documentation.

Generated research, captures and intermediate artwork belong in ignored `output/`. Only artwork used by the running game belongs in `public/art/`. Completion means these acceptance criteria work; it does not mean reproducing every World of Warcraft spell rank, quest, raid or online service.

Verified in release 1.0: 470 unit checks and 229 distinct browser cases across the complete sweep and final affected rechecks; 108 prepared endgame attempts; production build, formatting and repository asset audits. See [VALIDATION.md](VALIDATION.md) for results and limits.
